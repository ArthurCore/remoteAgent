## Findings
### BLOCKER
- None.

### HIGH
- **H1 — The integration project can report a fake green when it selects zero files.** `packages/db/vitest.config.ts:18-23` does not set `passWithNoTests` inside the `integration` project. A focused recorded run printed “No test files found” and exited 0 despite the outer default being false; a later rerun exited 1, confirming inheritance/merge behavior is not a sufficiently deterministic gate. This is B-owned configuration, not a complaint that D-owned tests do not exist yet. **Fix:** add `passWithNoTests: false` directly to the integration project's `test` object and verify the zero-file command exits nonzero before D lands.

### MEDIUM
- **M1 — Runtime inherits PostgreSQL's default PUBLIC EXECUTE on future routines.** `scripts/postgres/init-roles.sh:66-85` converges schema, table, and sequence privileges but never revokes PUBLIC routine execution; because runtime receives schema USAGE at `scripts/postgres/init-roles.sh:70`, a routine later created by migrator is executable by runtime through PUBLIC, contrary to the table/sequence-DML-only role model. Current B DDL has no routines, so this is latent rather than immediately exploitable. **Fix:** revoke EXECUTE on all existing routines in `public` from PUBLIC and add migrator-scoped `ALTER DEFAULT PRIVILEGES ... REVOKE EXECUTE ON ROUTINES FROM PUBLIC`; extend `packages/db/test/schema.spec.ts:365-392` with static assertions, while D proves the effective grants on real PostgreSQL.

### LOW
- None.

## Required decisions and non-findings
- **Zero-test exit:** unacceptable even during staged `B → C → D` delivery. D owns integration specs, but B owns the project definition and must make an empty selection fail closed.
- **Role threat model:** `scripts/postgres/init-roles.sh:17-45` is limited to generated ephemeral local/Testcontainers credentials. The quoted heredoc, `\getenv`, psql identifier/literal quoting, no xtrace, and non-argv passwords are appropriate; no secret or identifier-injection finding.
- The catalog-check/CREATE sequence at `scripts/postgres/init-roles.sh:35-40` has a theoretical concurrent-create race, but the declared official-image entrypoint is a single initializer. Sequential rerun idempotence is required; concurrent role bootstrap is not, so this is not a B finding.
- Sequence UPDATE at `scripts/postgres/init-roles.sh:76,85` permits `setval`, but the approved plan prescribes runtime sequence DML and B creates no application sequence. Treat this as a plan-level residual risk for the local role model, not a B deviation; production authority should revisit it before introducing public sequences.
- **Test quality:** `packages/db/test/schema.spec.ts:37-214,238-336` exhaustively freezes enum/table/column/key/check/FK/index and public-export metadata; `:339-392` appropriately limits B to Bash/static role assertions. SQL normalization at `:216-224` is somewhat implementation-coupled, but the real apply evidence closes syntax risk and D owns behavioral constraint/grant/idempotence proof. No brittleness finding.
- **Exports:** `packages/db/src/schema/index.ts:1-2` and `packages/db/src/index.ts:4` expose the intended root surface while preserving existing DB exports; the root package map already targets `dist/index.js`. No missing subpath/package-export finding.
- **D-owned empirical evidence:** fresh-database constraint negatives, cross-tenant rejection, role CRUD/DDL denial, effective routine/sequence grants, bootstrap rerun behavior, and migration behavior remain AW-008D-owned. The clean PostgreSQL apply is strong supplemental evidence, not a substitute for those tests and not a reason to charge their present absence to B.
